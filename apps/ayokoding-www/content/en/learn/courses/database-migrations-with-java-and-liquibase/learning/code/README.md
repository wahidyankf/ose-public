## Example code for database-migrations-with-java-and-liquibase

One folder per worked example: `ex-NN-<slug>/` holds `Main.java` (a small driver that opens JDBC to the pinned PostgreSQL 18 service container, runs a Liquibase changelog, and prints a deterministic verification), its changelog files (`changelog.sql`, `changelog.yaml`, or `changelog.xml` next to the program), its `run.yaml` (`toolchain: java`, `services: [postgres]`, `dependencies.lockfile: learning/code/jars.lock`, no network), and the recorded output under `expected/`. Multi-file units anchor every file in the lesson; the program and its output are always anchored. Every unit is deterministic: the harness runs it twice against one database, so seeds are delete-then-insert idempotent and history counts only grow on the first run; no clocks, no timings, no addresses in output. Liquibase runs under its LOGGER UI service with JUL silenced, so its progress narration never reaches stdout: the transcript holds only our own verification prints.

Shared conventions: `Main` silences the JUL loggers (`LogManager.reset()`) so only Liquibase's console UI and our own prints reach stdout; the JDBC host, user, and database come from the harness-provided `PGHOST`, `PGUSER`, and `PGDATABASE` variables; changelogs are addressed with the non-deprecated `DirectoryResourceAccessor` rooted at the unit directory. Rollback examples run `liquibase.rollback(...)` after `update` in the same program so the golden output shows both directions. Failure examples catch `liquibase.exception.LiquibaseException` and print its first line plus the history-table state, never a stack trace.
