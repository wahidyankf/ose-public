# Example code for database-migrations-with-java-and-spring-data-jpa

One folder per worked example: `ex-NN-<slug>/` holds `Main.java` (a small driver that boots Spring Data JPA, applies versioned migrations, and prints a deterministic verification), its `course/` support files (`JpaConfig.java`, `MigrationHistory.java`, `MigrationHistoryRepository.java`), its migration files (`V001__...sql` forward files and `U001__...sql` down files next to the program), its `run.yaml` (`toolchain: java`, `services: [postgres]`, `dependencies.lockfile: learning/code/jars.lock`, no network), and the recorded output under `expected/`. Multi-file units anchor every file in the lesson; the program and its output are always anchored. Every unit is deterministic: the harness runs it twice against one database, so ledger guards make reruns no-ops and history counts only grow on the first run; no clocks, no timings, no addresses in output. Spring, Hibernate, and HikariCP logging is silenced in every program, because framework narration differs between runs: the transcript holds only our own verification prints.

Shared conventions: `Main` resets the JUL loggers and sets the logback root level to OFF so only our own prints reach stdout; the JDBC host, port, user, and database come from the harness-provided `PGHOST`, `PGPORT`, `PGUSER`, and `PGDATABASE` variables with local defaults; versioned files sort into execution order by their numeric prefixes; rollback examples run down files in reverse version order in the same program so the golden output shows both directions. Failure examples catch the database error and print its stable SQLSTATE, never a stack trace.
