# Example code for web-backends-in-the-jvm-with-vertx

One folder per worked example: `ex-NN-<slug>/` holds `Main.java` (a small driver that builds a Vert.x Router, serves it on an operating-system-assigned loopback port, drives it with the Vert.x web client from the same process, and prints a deterministic verification), its `run.yaml` (`toolchain: java`, no services, `dependencies.lockfile: learning/code/jars.lock`, no network), and the recorded output under `expected/`. Multi-file units anchor every file in the lesson; the program and its output are always anchored. Every unit is deterministic: the harness runs it twice with no network, the port never reaches output, and no timings, thread names, or framework logs are printed, so the two executions agree byte for byte. The default 404 page is stable HTML and may appear in golden output where the example asserts it, but most examples install their own JSON 404 handler.

Shared conventions: `main` builds the Vert.x instance, builds the router through a `buildRouter` helper that takes the services the routes need, binds `127.0.0.1` with port zero and reads the assigned port back from the server, drives every check through one `check` helper that prints `METHOD path -> status body`, then closes the client, the server, and Vert.x in that order. JSON bodies are hand-written strings or `JsonObject.encode()` so key order is fixed; validation examples print the stable status plus the JSON error contract, never a stack trace.
