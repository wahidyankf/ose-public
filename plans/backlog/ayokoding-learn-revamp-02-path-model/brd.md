# Business Requirements — Path Model

## Problem

AyoKoding (`apps/ayokoding-www`) publishes learning paths: ordered routes through a shared library of
181 courses. A reader picks a path for a goal, such as "get interview-ready" or "learn accounting
for ERP work". Today the paths do not serve that goal:

- **No visible shape.** Each path is one flat list. The three software-engineer paths contain 116,
  114, and 121 courses (about 255 reading hours each) and share 111 courses. A reader cannot see which
  courses matter for the goal and which are optional depth.
- **Order that contradicts the goal.** The Interview-Ready path opens with the Neovim editor and puts
  its interview courses at positions 10, 27, and 64–66.
- **Prerequisites that encode an old journey, not real dependencies.** Course frontmatter
  `prerequisites` still chains an older linear sequence. For example, `just-enough-python` requires
  `capstone-forge-ready` (a Neovim capstone), and `data-structures-and-algorithms-essentials`
  requires `version-control-and-git`.
- **False claims.** The AI Engineer path calls itself "from scratch", yet 18 of its prerequisite
  edges point to courses outside the path.
- **Weak validation.** `core/manifest-integrity.ts` checks only unresolved and duplicate course IDs.
  Nothing stops an essential prerequisite from being missing or out of order.
- **Unready courses look ready.** 62 courses are skeleton outlines (under 1,000 words), yet paths
  list them exactly like complete courses.
- **Internal jargon on public pages.** The skills path pages say "Dangerous 1–4", "OI-2's doctrinal
  basis", and "no later plan appends courses", which only make sense to the people who planned the
  site. The paths hub and the career arc pages say "publishes as its manifest ships". This plan fixes
  the hub and career pages; plans 06 and 07 fix the skills pages when they restructure those paths
  (decision 39).

## Who This Is For

- **Readers** pick a path and want to know what to learn first, what they will be able to do after
  each phase, and what they need before starting.
- **Course and path maintainers** (later plans in this series) need a model that rejects a broken
  path automatically, so that rewriting a course never silently breaks a path.
- **Plan 04 (`learning-experience`)** needs phase titles, outcomes, core/extension kinds, and ordered
  course references to build the phase roadmap and progress tracking.

## User-Stated Requirements (verbatim intent)

- "Learn must be usable and reasonable: no confusing numbering, clear structure, clear entry points."
- Course quality: "make sure nanti semua coursenya harus lengkap ya. dan siap dipake" (every course
  complete and ready to use). This plan does not write courses. It makes unready courses visible
  and keeps them out of every core.
- "Delivery checklists: detailed, split by phase, with an explicit completion gate per phase or
  section."
- "jangan kerjain/implement plan ini sebelum gw kasih perintah buat eksekusi" (do not implement this
  plan until the user gives the command to execute).

Decisions 6 and 17 collide for skills paths: every skills course is an outline today, yet every
skills course must be core. Decision 39 resolves the collision by timing: the skills paths become
phase-structured only when their courses stop being outlines. Until then decisions 16–18 do not apply
to them, and decision 6 is never narrowed, because no skills path has a core in this plan's sense
(see [tech-docs/002](./tech-docs/002-manifest-schema-and-migration.md#skills-paths-pending-restructure)).
The user's words, 2026-10-09: "bikin sekalian. semua yang kerangka harus diisi" ("do it all at once;
every outline must be filled"), then the choice "Skills path ikut plan konten" ("skills paths follow
the content plan").

## Business Risks

| Risk                                                        | Mitigation                                                                                                                                                                              |
| ----------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Readers who bookmarked a course in a path lose their place  | URLs do not change: course slugs and `?path=` stay the same; only the order of extension courses moves                                                                                  |
| The skills marker outlives its reason or spreads to careers | The allowlist is closed and keyed by exact path ID; tests prove a career path cannot carry the marker and that every allowlist entry is used; plans 06 and 07 must remove their entries |
| Skills readers still meet outline courses and old jargon    | Accepted until plans 06 and 07 ship; the user chose to fix both together with the filled courses (decision 39)                                                                          |
| A cut-down core looks like the site removed courses         | Extensions stay listed under an "Optional extensions" heading; membership test proves nothing was dropped                                                                               |
| Plan 03 lands first and also edits `frontmatterSchema`      | Phase 0 detects it and rebases; the two changes touch different keys                                                                                                                    |
| Revised prerequisites hide a real dependency                | Rubric plus a per-edge evidence table; edges are kept whenever the course's own prose names them                                                                                        |
