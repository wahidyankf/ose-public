# The `ayokoding-cli` Project and HIPPO Parity

Decision 37 asks for:

- a Go + Cobra CLI at `apps/ayokoding-cli`;
- the roots-be layout and targets;
- the ferret-cli/crane-cli product shape;
- the repository's command-line-interface convention;
- the HIPPO strictness bar, with a side-by-side table that proves parity or justifies each
  difference.

HIPPO is the sibling repository `github.com/wahidyankf/hippo`. It was read as a reference on
2026-10-09 and is never edited by this plan.

## Project Layout

```text
apps/ayokoding-cli/
├── cmd/ayokoding-cli/main.go          # calls bootstrap; nothing else
├── internal/
│   ├── domain/                        # pure: no os, os/exec, net, syscall, cobra
│   │   ├── runspec/                   # run.yaml model, strict decode from bytes, validation
│   │   ├── catalog/                   # toolchain catalog model, decode, digest rules
│   │   ├── layout/                    # unit discovery and layout findings over an fs.FS view
│   │   ├── anchors/                   # anchor grammar, fence classes, sync findings, fence rewrite
│   │   ├── containerplan/             # argv construction for docker run, services, builds
│   │   ├── selection/                 # opt-in, affected mapping from changed paths, shards
│   │   ├── coverage/                  # unit and fence coverage per course
│   │   ├── simulation/                # summary-line parsing for simulation runs
│   │   └── finding/                   # closed finding and error-code vocabulary
│   ├── application/                   # use cases: Validate, Sync, Run, Coverage, Check, Affected, Toolchains
│   ├── adapters/
│   │   ├── cli/                       # Cobra tree, flags, text and JSON rendering, exit mapping
│   │   ├── containers/                # executes argv through the container CLI; timeouts; cleanup
│   │   ├── git/                       # changed paths since a revision
│   │   └── content/                   # os.DirFS views, temporary copies, sync writes
│   └── bootstrap/                     # wiring; imported only by cmd
├── toolchains/                        # catalog.yaml, <id>/Dockerfile, toolchains.go (go:embed)
├── scripts/
│   ├── coverage-gate.sh               # unit tests with -race, coverage run, 99% floor, unit BDD
│   ├── test-e2e.sh                    # stamped build, then the E2E BDD adapter
│   └── compat-min-version.sh          # asserts go.mod's go directive
├── tests/
│   ├── architecture/                  # import rules over the production graph, negative fixtures
│   ├── bdd/                           # godog suite; AYOKODING_BDD_ADAPTER=unit|integration|e2e
│   ├── coverage/                      # coverage threshold helper (go run ./tests/coverage)
│   ├── integration/                   # temp dirs, fake container CLI, real git, signals
│   ├── support/                       # shared test helpers and the fake container CLI source
│   ├── fixtures/cli-conformance/      # local copy of the CLI conformance assertion corpus
│   └── testdata/courses/              # fixture course trees (green, broken, inert, static, simulation)
├── .golangci.yml
├── .gitignore                         # dist/, coverage/
├── go.mod, go.sum                     # module github.com/wahidyankf/ose-public/apps/ayokoding-cli
├── project.json
├── behaviour-coverage.json
├── README.md, CHANGELOG.md, CONTRIBUTING.md
└── LICENSE                            # already tracked; kept
```

`internal/domain` reads course files only through an `fs.FS` value given to it. Application use
cases receive ports (`ContentSource`, `ContainerRuntime`, `ChangeSource`) declared in the consuming
package, as the Go standard requires. Unit tests pass `fstest.MapFS` and in-memory fakes; no unit
test touches the disk, a child process, or the network.

## Command Tree

```text
ayokoding-cli [--output text|json] [--color auto|always|never] [--no-input] [--content DIR] [--catalog FILE]
├── examples
│   ├── validate  [--course SLUG]... [--include-inert]           layout + run.yaml + catalog references
│   ├── sync      [--course SLUG]... [--include-inert] [--write]  lesson fences against files
│   ├── run       (--course SLUG... | --since REV | --all) [--shard K/N] [--unit PATH]
│   │             [--seed N] [--record] [--single-run]
│   ├── coverage  [--course SLUG]... [--min-percent N]
│   ├── check     (--course SLUG... | --since REV | --all) [--shard K/N]
│   └── affected  --since REV                         prints the selection only
├── toolchains
│   ├── list
│   └── build     [ID]...
└── help [COMMAND]
```

- `--content` defaults to `apps/ayokoding-www/content/en/learn/courses`, relative to the working
  directory. Nx runs from the repository root.
- `--catalog` defaults to the embedded catalog. A file given here goes through the same validation,
  so it is still digest-pinned. Tests use it, and so does a content author trying a new toolchain
  before adding it. CI never passes it.
- `validate`, `sync`, and `coverage` cover every opted-in course when no `--course` is given.
  `--include-inert` makes `validate` and `sync` also preview every course that has not opted in,
  which gives content plans a baseline. `--write` never applies to an inert course unless that
  course is named with `--course`.
- `run` and `check` need exactly one selection: `--course`, `--since`, or `--all`. Anything else is a
  usage error, exit 2.
- `check` runs `validate` and `sync` over every opted-in course, because both are cheap and static.
  It then runs the selected courses and prints the coverage report (minimum 0).
- `--shard K/N` sorts the selected courses by slug and keeps every N-th course starting at K. The
  split is stable and needs no state.
- `--record` writes only missing expected files and never overwrites one.
- `--seed N` is the replay mode described in [tech-docs/006](./006-determinism-and-simulation.md).
- The tool never prompts, so `--no-input` is accepted and has no further effect.
- `toolchains build` builds derived and environment images. `AYOKODING_BUILDX_CACHE=<dir>` adds
  local buildx cache flags.

### Streams, Output, and Exit Statuses

- **Standard output** carries the payload only. In text mode that is the findings and the per-course
  summary. With `--output json` it is one JSON document with `"schemaVersion": 1`. The document holds
  no durations, timestamps, or absolute paths, so the same inputs give the same bytes.
- **Standard error** carries progress lines, durations, and diagnostics. Under `--output json` an
  error is a JSON body
  `{"schemaVersion":1,"error":{"code":"ayokoding.<area>.<reason>","message":"..."}}`.
- **Color** follows `--color`. In `auto` mode, any value of `NO_COLOR` disables color. There is no
  TTY detection for output format; JSON is chosen only by `--output json`.
- **Exit statuses** are published in `--help`:

  | Status | Meaning here                                                                                                                       |
  | ------ | ---------------------------------------------------------------------------------------------------------------------------------- |
  | 0      | Everything selected is green: no finding, every run passed, coverage at or above `--min-percent`                                   |
  | 1      | The work completed and the result is negative: a finding, a failed or timed-out run, nondeterminism, or coverage below the minimum |
  | 2      | Bad usage, bad configuration (for example an unpinned catalog image), or an internal failure, including a recovered panic          |
  | 124    | A service did not become ready in its bounded wait                                                                                 |
  | 125    | The container runtime refused (daemon unavailable, pull failed)                                                                    |
  | 126    | The container CLI was found but cannot run                                                                                         |
  | 127    | The container CLI, or `git` when `--since` needs it, was not found                                                                 |
  | 130    | Interrupted; running containers and networks are removed first                                                                     |
  | 141    | Standard output was closed by the reader                                                                                           |

- **Error codes** come from the closed vocabulary in `internal/domain/finding`:
  - finding codes `ayokoding.layout.*`, `ayokoding.runspec.*`, `ayokoding.sync.*`,
    `ayokoding.examples.*`, and `ayokoding.coverage.below-minimum`, which are items in the payload;
  - error codes `ayokoding.usage.*`, `ayokoding.config.*`, `ayokoding.catalog.*`, `ayokoding.env.*`,
    and `ayokoding.internal.panic`, which are error bodies.

  A new failure mode gets a new code, never a new status.

`behaviour-coverage.json`:

```json
{
  "project": "ayokoding-cli",
  "corpus": ["../../specs/apps/ayokoding/cli/behaviours"],
  "adapters": {
    "unit": { "bindings": ["tests/bdd"], "driver": "go.mod" },
    "integration": { "bindings": ["tests/bdd"], "driver": "go.mod" },
    "e2e": { "bindings": ["tests/bdd"], "driver": "go.mod" }
  }
}
```

One step-definition package serves all three adapters. Each step calls a `driver` interface whose
implementation is chosen by `AYOKODING_BDD_ADAPTER`:

- **unit:** in-process, with `fstest.MapFS` and a fake runtime;
- **integration:** an in-process command against temp dirs, the fake container CLI, and real git;
- **e2e:** the built binary and real Docker.

The suite runs with `Strict: true`.
