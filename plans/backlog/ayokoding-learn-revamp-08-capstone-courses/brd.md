# Business Requirements — Capstone Courses

## Problem

AyoKoding (`apps/ayokoding-www`) has eight capstone courses that promise a finished project and teach
nothing. A capstone is where a learner joins the ideas of earlier courses in one runnable thing, and
today these eight cannot do that:

- **Every one is an empty outline.** Each of the 8 courses has three hand-written pages and 216 to 395
  words in total (2,143 words for all eight). There are no lessons, no worked examples, no exercises, and
  no project. The only code is a 34-line file pair in the coding-agent course, with no way to run it.
  A learner who opens "Build Your Own Coding Agent" reads a short paragraph and a list of titles.
- **The AI Engineer path has no goal.** Its natural goal is the coding-agent capstone, but a course that
  is an outline may never be in a path's core (series decision 6). So plan 02 leaves the path without a
  goal and with a hand-curated core of 25 courses that nothing checks. A path that cannot name what the
  learner will have built is a reading list, not a path.
- **Nothing says what a capstone must be.** The repository has four tutorial modes and none is for a
  project. The "capstone" label in the course catalog says "integration project" and nothing about how it
  teaches, what it must prove, or how a reader knows they finished.
- **Two of the courses are security projects.** A pentest engine and a secure service can easily turn into
  attack tutorials. Without a written safety boundary and a way to check it, a well-meant lesson can end
  up as operational attack material in a public repository.
- **Some tests lean on the gaps.** One browser test uses `capstone-data-pipeline` because it is the one
  real course whose "Start" button must fall back to a capstone page, and tests from plans 02 to 04 use a
  real outline course as their example. When this plan fills the last outlines, those tests would fail.
- **The harness has never carried this much.** About 358 code units must each run twice in CI. Nobody has
  measured whether that fits the time limit.

## Who This Is For

- **Readers:** junior bootcamp graduates and developers who have finished a few courses and want to
  prove, with something running, that they can join the ideas together. They need a clear brief, steps
  they can check, and a way to judge their own work. The rubric and the acceptance criteria are written
  for them.
- **AI Engineer path learners:** people who write code and want to build AI systems. The path ends in the
  coding-agent capstone; its core is exactly what they need to reach it.
- **Later plans:** plans 09 to 13 rewrite and audit the courses these capstones depend on, and plan 14
  checks the series end state. They need the coupling between a capstone and its prerequisites to be
  written down and checked, so they know what to re-read.

## Business Risks

| Risk                                                                                      | Mitigation                                                                                                                                                                                                                                  |
| ----------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A course cannot pass a gate within 2 cycles                                               | It is marked BLOCKED, recorded, and reported; the batch moves on. Before the metadata and path phases the plan stops for the user, because the end-state gate needs all eight. If the coding agent is BLOCKED, the AI path phase is skipped |
| A security lesson becomes attack material                                                 | A written safety boundary in each of the 3 courses; an in-process fixture lab with no network; the author, search, and gate checks; a scan in the content-shape test; any operational detail is a CRITICAL finding                          |
| 358 units do not fit the CI time limit                                                    | Measure first; a four-rung ladder (author for speed, count shards by units, raise the timeout, stop and report); no course is ever weakened to fit                                                                                          |
| Plans 09 to 13 rewrite a prerequisite and a capstone becomes wrong                        | Course-level coupling (links, restated concepts, own copies, a `relies-on` table), a test that fails first on a renamed or removed prerequisite, and written duties for plans 09 to 14                                                      |
| Plans 02, 03, or 05 merge with different names than this plan expects                     | Phase 0 checks every name on `origin/main`, recomputes the AI closure from the merged graph, and records the merged names before any change                                                                                                 |
| Shrinking the AI core from 25 to 12 surprises the user                                    | It is flagged as a product-shape change in the README and the PR; nothing is deleted (16 courses move to named extension phases); adding a second goal is a one-line manifest change that the closure test verifies                         |
| External facts change (OWASP list, ATT&CK version, NIST SP 800-115 status, SRE numbers)   | Phase 0 re-reads each official page; any difference corrects every table in the courses; the Content Quality Gate checks sources and dates                                                                                                  |
| The volume is large (about 156,000 words and 358 units)                                   | It follows the mode's floor and the user's instruction to fill every course; one commit per course, per-course gate reports, and a committed execution summary let a reviewer check each course alone                                       |
| Running many container-based examples overloads the machine                               | Every command runs through HIPPO, which admits harness runs one resource budget at a time; at most 3 background agents                                                                                                                      |
| Removing the last real outline course leaves browser tests without a case                 | The exemptions record why, Unit proves each scenario over fixtures, and the product code for the outline status stays for a future course                                                                                                   |
| The plan quality gate has not run, so the plan may carry defects that the gate would find | It is the first step of Phase 0, with 2 cycles; a `BLOCKED` verdict stops execution and is reported to the user                                                                                                                             |
