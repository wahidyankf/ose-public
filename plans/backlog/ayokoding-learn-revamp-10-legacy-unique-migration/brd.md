# Business Requirements — Legacy Unique Migration

## Problem

AyoKoding (`apps/ayokoding-www`) carries two parallel learning surfaces: a 181-course catalog built by
plans 01 to 09, and `content/en/learn/legacy/`, 1,150 Markdown files (about 6.65 million words) left over
from the site's pre-revamp structure. The legacy tree's own `_index.md` and `overview.md` say it is "kept
for reference while the course library fills", but nobody has ever checked which of its topics the course
library actually fills:

- **Some legacy topics teach a subject no course teaches at all.** Four named AI coding-agent tools
  (Claude Code, Hermes Agent, OpenClaw, Pi coding agent), eleven per-language database-migration tools,
  eight per-language web backend frameworks, twelve programming languages in depth beyond their
  `just-enough-X` primer, and a dozen smaller topics (Playwright, text-processing tools, corporate
  finance, Datomic, and others) exist only in the legacy tree. A learner who needs one of these subjects
  finds it only in a tree the site itself calls disposable.
- **Some legacy topics duplicate a course that already exists.** Git, Docker, Kubernetes, SQL, React, DDD,
  and dozens of others are taught in both places, at different depth and in a different voice, with no
  record of which one a learner should trust.
- **Nobody has ever decided which is which, with evidence.** Without that decision, deleting
  `learn/legacy/` (which series decision 34 requires before the series can call itself done) risks
  silently deleting subjects nothing else teaches.
- **94 `docs/` files link into the legacy tree**, mostly `docs/explanation/software-engineering/**`
  "learning path" prerequisite links the SE-separation convention requires before a standards page.
  Deleting the legacy tree without first recording where each of those 94 files should point instead
  breaks every one of them.
- **308 URLs need a redirect** when the legacy tree is finally deleted (plan 14), and a redirect needs a
  destination; nothing today records what that destination is, topic by topic.

## Who This Is For

- **Learners who need one of the 48 missing subjects:** a bootcamp graduate or working developer who
  wants to learn Claude Code, a specific database-migration tool, a specific web backend framework, or a
  programming language in depth, and today can only find it in a tree the site tells them is temporary.
  They need a real course, to the same definition of done as every other course in the catalog.
- **Plan 14's author:** the person (or agent) who deletes `learn/legacy/`, adds its redirects, and
  repoints the 94 `docs/` files. They need one machine-checkable artifact that tells them, for every one
  of the 1,150 files, what happened to it and where its URL should now point, without re-deriving the
  classification themselves.
- **Plans 11 to 13's authors:** the people who audit the 111 other pre-existing courses. They need to know
  which legacy topics this plan judged `covered` by which existing course, so they can treat that legacy
  material as optional source evidence during their own audit, without re-measuring the same comparison.
- **PR reviewer:** the person who reviews this large PR. They need one commit per course, per-course gate
  reports, and the mapping table itself as a reviewable, checkable artifact (not a narrative claim).

## Business Risks

| Risk                                                                                                              | Mitigation                                                                                                                                                                                                                                                                          |
| ----------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A course cannot pass a gate within 2 cycles                                                                       | It is marked BLOCKED, recorded, and reported; the batch moves on. The wave gate stays open until the user decides; the end-state gate needs all 48 resolved before the PR can claim the series share.                                                                               |
| 48 courses is a very large PR                                                                                     | 16 waves of 3, one commit per course, per-course gate reports, checkpoint pushes after each wave; see [delivery.md](./delivery.md#wave-strategy-and-pr-size-risk) for the explicit size-risk statement.                                                                             |
| A fast-changing AI tool's documented behaviour is wrong by the time a reader opens the course                     | Every runnable example drives a deterministic fixture shim, not the live product, so the course never depends on current vendor behaviour staying true; the stated accuracy policy sets the expectation.                                                                            |
| Adding one toolchain (WebAssembly) and extending two (Clojure, Kotlin) destabilizes the harness for other courses | Plan 05's own procedure requires a full examples run after any toolchain change; that run is scheduled and its result recorded before the courses depending on a changed entry are marked done. It also re-proves plan 09's Java units, because the shared `JarFetch.java` changes. |
| The `covered` classification is later found wrong (an existing course does not actually match)                    | The mapping table's Evidence column states the specific comparison made, so a reviewer or a plan 11 to 13 auditor can check it and, if wrong, file a correction before plan 14 deletes the legacy source.                                                                           |
| The mapping file and the real course slugs drift (a course is renamed after this plan merges)                     | [syllabus/README.md](./syllabus/README.md) states explicitly that any later slug change must be mirrored in the mapping table in the same commit; plan 14's Phase 0 re-validates every slug before use.                                                                             |
| Running many container-based (PostgreSQL) examples overloads the machine                                          | Every command runs through HIPPO, which admits harness runs one resource budget at a time; at most 3 background agents.                                                                                                                                                             |
| The plan quality gate has not run, so the plan may carry defects that the gate would find                         | It is the first step of Phase 0, with 2 cycles; a `BLOCKED` verdict stops execution and is reported to the user.                                                                                                                                                                    |
