# Legacy to Course Mapping

This is the machine-checkable artifact plan 14 (`legacy-removal`) consumes to build its 308-redirect
set and to repoint the 94 `docs/` files that link into `learn/legacy/`. It is produced by inventorying
every directory under `apps/ayokoding-www/content/en/learn/legacy/` that directly holds Markdown files
(1,150 files total, measured 2026-10-09 by a recursive file-system walk), and judging each one of three
ways, with evidence:

- **Covered** — an existing, filled course already teaches the same subject at a comparable or
  superseding depth. The legacy pages are not deleted by this plan (that is plan 14's job); a maker
  auditing or rewriting the target course later (plans 11 to 13) may mine the legacy pages as source
  material, but must re-verify every fact rather than copy it as already correct.
- **New course** — no existing course teaches the subject at a comparable depth. This plan writes a new
  course to the series definition of done (decision 27); its brief is linked in the Target column.
- **Obsolete** — the content is not migrated to any course, with a stated, evidenced reason (a bare
  navigation page, a proprietary third-party assessment framework with no fitting category, or similar).

## Row format (exact, for plan 14's mechanical consumption)

Each data row of the table below has exactly these six columns, in this order. The seventh item is not a
column: plan 14 derives it from the Disposition and Target columns.

1. **Legacy path** — relative to `apps/ayokoding-www/content/en/learn/legacy/`, backtick-quoted. A path
   ending in `.md` is one file; a path with no extension is every Markdown file directly or transitively
   under that directory.
2. **Files** — the file count this row's legacy path covers.
3. **Words** — the whitespace-token word count across those files (frontmatter excluded), measured
   2026-10-09.
4. **Disposition** — exactly one of `covered`, `new`, `obsolete`.
5. **Target** — for `covered`, the comma-separated slug(s) of the existing course(s) that already teach
   this subject. For `new`, the single slug of the new course this plan writes (every `new` slug below has
   a brief at [`syllabus/courses/<slug>.md`](./courses/)). For `obsolete`, a literal `-`.
6. **Evidence** — the specific comparison this plan made (an existing course's description, a measured
   mention count, a direct title/example comparison, or a stated legal/taxonomy reason) and why it
   resolves the row's disposition.
7. **Redirect destination for plan 14 (derived, not a column)** — `/en/learn/courses/<target-slug>` for `covered` (first-listed
   target) and `new` rows; `/en/learn/courses` (the catalog, the stated fallback) for `obsolete` rows.

Plan 14 derives its redirect rule set from this table at whatever URL granularity it needs (this table is
topic-directory granularity; plan 14 also generates rules for nested sub-paths this table does not enumerate individually, such as a topic's own `overview.md`,
`by-example/`, or `in-the-field/` children, each inheriting its parent topic row's destination unless plan
14 finds a more specific one). A row's **Target** column, not its **Evidence** column, is the field plan 14
parses; **Evidence** is prose for a human reviewer only.
