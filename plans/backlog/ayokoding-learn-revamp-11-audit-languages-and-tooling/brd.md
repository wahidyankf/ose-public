# Business Requirements — Audit of Language and Tooling Courses

## Problem

AyoKoding (`apps/ayokoding-www`) has 32 courses on programming languages, engineering tools, and
infrastructure that readers can open today. They are not outlines, and most sit in the three
software-engineer learning paths. A reader who follows a path meets them as real steps, but they do not meet the
series definition of done:

- **Many are short of their floor.** 21 of the 32 are below the word floor of their mode, by 305,207 words in
  all. `just-enough-rust` has 78 example headings over 4,710 words, and `just-enough-java` has 80 examples,
  6,315 words, and no code fence in any lesson. Another 24 courses have a drilling page
  under 5,000 words (95,746 words short in all).
- **No example is proven to run.** None of the 32 courses has a `run.yaml`, so the code harness (plan 05) checks
  nothing in them. Four primers (`just-enough-dart`, `just-enough-kotlin`, `just-enough-rust`,
  `just-enough-swift`) keep their programs only inside lesson fences or in one project, so 86 units each have to
  be created.
- **Lessons and files disagree.** 494 anchors do not match the file they point at, and
  1,368 code fences and 792 `Output` blocks are not tied to a file at all. A reader who
  copies a lesson's code may get a program that differs from the one the course says it ran.
- **Some examples cannot be trusted as written.** Examples that print a clock, a random value, a map order, or a
  temporary path cannot be recorded; 91 files of `version-control-and-git` use `mktemp` for paths that reach
  output. Tools that a sandbox cannot host (a hypervisor, `perf`, a cloud API, a cluster) are shown as if they
  ran.
- **Five courses are templated filler.** Plan 09's filler guard flags `just-enough-cpp`, `just-enough-go`,
  `just-enough-java`, `building-production-cli-tools`, and `cicd-and-release-engineering`, and tags them for this
  plan to fix.

## Who This Is For

- **Readers:** software engineers who learn a language or a tool on AyoKoding and expect each course to be
  finished: accurate text, examples they can run, and drilling to test themselves. Most arrive through a
  software-engineer learning path.
- **Authors and maintainers:** people who edit a course after merge. They need a test that stops a finished course
  from becoming thin again and a harness that tells them when an example stops running.
- **Later plans:** plans 12 and 13 audit the other pre-existing courses with the same method, the same registry,
  and the same CI decisions; plan 14 proves the series end state.
- **The PR reviewer:** one person reviews a very large PR and needs a commit per course and a record of each
  course's gates.

## Business Risks

| Risk                                                                                                    | Mitigation                                                                                                                                                                                                                                     |
| ------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| The gap-fill is very large: about 312,328 words and 826 new units to write                              | Size classes split big courses into packets; waves of at most three courses; a course that cannot finish in 2 cycles is BLOCKED, restored, and reported, and the user decides to retry, defer, or stop. The plan never lowers a target quietly |
| The PR is too large to review as one listing (about 8,000 to 10,000 changed files, a planning estimate) | One commit per course, a committed execution summary, and four checkpoint pushes with a draft PR from the first; the PR gate reads git SHAs and is not limited by GitHub's 3,000-file listing. Phase 2 probes what the page shows              |
| The CI budget is exceeded: four shards never fit at planning figures                                    | The response ladder (rungs 2b, 2c, 3, 4) decided on Phase 1 measurements; eight shards with a 120-minute timeout fit; a course that still does not fit is BLOCKED with the cause "does not fit the CI budget", never weakened                  |
| Rewriting 826 units produces templated output that fires the filler guard                               | Makers write from each example's own code and output; the guard runs at CP-2 and CP-6; the five baseline entries are removed in the course commits; a course that fires is fixed and never baselined                                           |
| Plan 09's Java recipe or its Spring probe (P9) fails and the `java` image changes                       | Phase 0 builds and smoke-tests the `java` and `kotlin` images; none of the 32 courses uses Spring; a failing image stops Phase 0 and is reported                                                                                               |
| A rewritten course breaks a figure that another course copies (SRE budget numbers)                      | The two known figures are listed in the brief and kept as they are; the checker searches for them                                                                                                                                              |
| A prerequisite edit changes the AI Engineer core                                                        | Rule AI-1: no such edit without the rubric and green integrity tests; otherwise a `needs-decision` row for the user                                                                                                                            |
| Models and static checks mislead readers about what ran                                                 | Rule TC1: every modelled or statically checked example says so beside its fence; the Content Quality Gate judges it                                                                                                                            |
| Plans 02, 03, 05, 08, or 09 merge with different names than this plan expects                           | Phase 0 checks every name on `origin/main` and records the merged names before any change                                                                                                                                                      |
| Running many container-based examples overloads the machine                                             | Every command runs through HIPPO, which admits harness runs one resource budget at a time; at most 3 background agents                                                                                                                         |
