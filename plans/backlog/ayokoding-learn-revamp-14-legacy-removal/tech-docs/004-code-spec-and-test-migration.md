# 004 — Code, Spec, and Test Migration

This page says what changes in the application, in the specifications, and in every test layer so that
nothing refers to the legacy bucket, and so that the behaviour the bucket used to carry (rendering
coverage, redirect coverage) is still proven afterwards. The measured list of references is in
[001](./001-current-state-and-evidence.md#what-references-the-legacy-tree-today-the-measured-list); this
page gives each item an id, an action, and the proof that replaces it.

Ids: **A** application code, **S** specification, **T** an existing test file that changes, **N** a new
file, **C** content outside the tree.

## Rules for this migration

1. A reference is removed or retargeted. It is never left behind a flag or a comment such as "legacy,
   kept for now".
2. A test that exercised a legacy page for a general reason (code highlighting, tabs, math) keeps its
   purpose and gets a stable page to run on ([rendering fixture](#rendering-fixture)). Deleting it would
   delete coverage of the renderer.
3. A test that asserted the bucket itself (three buckets, noindex, sitemap lists legacy) is flipped to
   assert the absence, or deleted when absence is already proven by a stronger test.
4. Everything content-driven is **verified, not edited** ([the content-driven
   table](#content-driven-surfaces-verified-not-edited)).
5. Hippo wraps all compute; every command in [../delivery.md](../delivery.md) names its class and tier.

### The two censuses that found hidden dependencies

The bucket grep in [001](./001-current-state-and-evidence.md) finds what names the bucket. It cannot find a
test that depends on legacy content without naming it. Two further censuses were run, both measured
2026-10-10, and Phase 0 repeats both on the as-merged tree:

1. **URL-literal census.** Every string literal that starts with `/en/` or `/id/` in the app's tests, both
   e2e projects and the specs (121 distinct literals) is checked against the content tree. 13 literals
   point into `learn/legacy` (all in the T-list); the other 108 are existing pages, tools and browse
   routes, path landings built from manifests, mock slugs, or redirect samples, except three: the pre-IA
   addresses in `architecture-cases-routes.feature` (S6).
2. **Text-literal census.** Every string literal of 10 or more characters with a space in the integration,
   fe-e2e and be-e2e tests (and the unit tests) is looked up in the legacy tree, in all other content, and
   in `src/`. Literals found **only** in the legacy tree and that are assertions on page text: "Legal and
   Ethical Notice" and "Only use Gobuster on systems you own or have explicit written permission" (T11,
   replaced by the fixture's own words) and "Spring Security Basics" (T19). The rest of the 32 raw hits
   are code fragments or mock data.

Phase 0 repeats both censuses and an unclassified hit stops execution. The commands are in
[../delivery.md](../delivery.md#phase-0-groundwork-and-readiness). They run the repository's own
`rtk git grep`, not a script: the URL census is
``rtk git grep -n -E "[\"'\`]/(en|id)/" -- apps/ayokoding-www/tests apps/ayokoding-www-fe-e2e/tests apps/ayokoding-www-be-e2e/tests specs/apps/ayokoding/www``
and the text census checks each listed assertion text with
`rtk git grep -l -F "<text>" -- apps/ayokoding-www/content` (expected: only legacy paths).

### Fixing the shared simulator (N2)

The simulator in T2 handles a wildcard rule only when both the source and the destination end in
`/:path*`: it slices seven characters off the destination to rebuild the tail. The new rules have a
wildcard source and a **static** destination (`/en/learn/courses/rust-in-depth`). Without a change the
helper would cut the last seven characters off a course path and produce a wrong destination, silently
passing wrong expectations or failing every wildcard case.

Rule for `applyOne`: if a rule's destination ends in `/:path*`, rebuild it from the matched tail (the
existing behaviour, still needed by `course-rehome`, `content-namespace`, `learn-reorg`, and
`locale-entry`); otherwise return `destination` as is. The first test written for N2 is the failing case
that proves this: a wildcard source with a static destination returns the destination whole. A second test
covers a loop (a rule pointing to itself) and the eight-hop limit, which the old file had no direct test for.

## Rendering fixture

**Problem.** Six fe-e2e scenarios (T11) and one copy-button scenario (T12) prove the renderer with
legacy pages because those pages used every shortcode. Measured: the callout, steps and tabs shortcodes
(`{{< callout >}}`, `{{% steps %}}`, `{{< tabs >}}`) appear in 60 legacy files and in **no** file outside
the tree. Without a replacement, deleting the tree deletes the only end-to-end proof that the renderer
supports them.

**Design.** One draft page, `content/en/learn/e2e-fixture-rendering.md`, mirrors the existing Indonesian
fixture (`content/id/belajar/e2e-fixture-blok-kode.md`: `draft: true`, high `weight`, an
"E2E fixture" description). A draft is read only when `AYOKODING_WEB_SHOW_DRAFTS=true`, which the fe-e2e
build already sets, so it never reaches the public site, sitemap, search data, or the committed
`_index.md` link lists (the index generator reads through the same filter).

Front matter: `title: "E2E Fixture Rendering"`, `description: "E2E fixture: one page that carries every
renderer feature the end-to-end suite checks, so the suite does not depend on lesson content."`,
`weight: 990`, `date: <authoring date>`, `draft: true`. The body holds, in this order, so each scenario can
use one stable element:

| Scenario (fe-e2e)                                        | Element the body carries                                                                          | What the assertion keeps                                                          |
| -------------------------------------------------------- | ------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| fenced code block (highlight, language label, monospace) | a ` ```go ` block of about six lines                                                              | `pre[data-language="go"]`, the label text `go`, tokens, font                      |
| callout shortcode                                        | `{{< callout type="warning" >}}` with a title line "Legal and Ethical Notice" and a body sentence | warning alert, icon, the two texts (assertions edited to the fixture's own words) |

The fixture also acts as the "prose" page for any step that needs a heading and several paragraphs; the
prose scenario keeps using `/en/learn` (plan 04's Learn home), so the fixture is not asked to do more
than it must.

**Exclusions that keep the site clean.**

1. It is a draft, so `reader.ts` and `repository-fs.ts` skip it in production.
2. The Learn sidebar in the e2e build contains it as the last child (weight 990). T15 asserts relative
   order and "no Legacy" instead of an exact list, for that reason.

4. The content integrity tests that count pages (course catalog counts of plan 03 and plan 10) look
   under `learn/courses`, not under `learn/`. Phase 0 confirms with
   `rtk git grep -n "content/en/learn" -- apps/ayokoding-www/tests` that no test counts direct children
   of `learn/`.

If the as-merged renderer has gained or lost a shortcode, the fixture follows the renderer: Phase 0 reads
the six scenarios' current assertions and the fixture carries exactly the elements they use.

## The deletion itself

One commit, the last one that changes product, test, or document files, removes
`apps/ayokoding-www/content/en/learn/legacy/`, the temporary tests and fixtures (N4, N5, the docs map), and
plan 10's tree-walking test and feature (T17, S9). It regenerates `learn/_index.md` (C1) and carries the
edits that only make sense once the tree is gone: A6, A7, A8, C3, the absence scenarios, and the flipped
sitemap and sidebar assertions. `learn-three-bucket.ts` (A1) and the tests that import it go earlier, in the
Phase 2 commit that swaps in the new module, because the new module replaces it. The full commit order is in
[../delivery.md](../delivery.md#phase-5-the-deletion) and the list of removals in
[010](./010-pr-size-rollback-and-series-closure.md#what-the-last-commit-removes). Deleting the tree with
`rtk git rm -r` is a file operation, not a script; the count `1,150` is asserted before (`find` count) and
after (the directory is gone).

## Hidden dependencies

The measured list can miss a test that depends on the tree in a way no grep catches (for example a
search test that happens to search for a term only legacy pages contain). The plan does not guess. After
the deletion commit it runs the complete suites (unit, unit-fe, integration, fe-e2e, be-e2e) once. A
failure is classified as: **caused by the removal** (fix the test in this pull request, at most two fix
cycles), **unrelated and pre-existing** (confirm on `origin/main`, record, leave), or **a content problem
in a course** (stop and report; courses are not this plan's to rewrite). After two cycles with a failure
caused by the removal still open, the delivery unit is not ready and the plan reports instead of
continuing.
