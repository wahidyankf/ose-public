Phase 16b-2 — 5-case trigger matrix (private-sibling), mirroring Phase 9b-2

Method: isolated throwaway git fixture (/tmp/wf16-fixture, git init, no origin — same
pattern as Phase 16a's RED proof), containing only a minimal repo-config.yml with the
two new gate entries (governance-word-budget, governance-readme-completeness) copied
verbatim from private-sibling's repo-config.yml. With no origin/main, gate run's pre-push
candidate-path resolution falls back to staged_paths() (merge_base_paths' documented
fixture fallback), so staging a file simulates a pre-push/CI trigger check. Each case:
stage the file, run `gate run --surface=pre-push --only=<gate-id>` for both gates,
observe whether "Running gate <id>" prints (trigger matched) or nothing prints (silent
skip — path-gated trigger mismatch is a silent `continue`, confirmed in
apps/rhino-cli/src/commands/gate/run.rs lines 171-177).

Note: a live test against the real private-sibling working tree (staging the actual
Phase 16 files) does NOT exercise this path — `gate run --surface=pre-push`'s
candidate-path source for a real repo with an origin is `git diff --name-only
<merge-base with origin/main> HEAD` (committed diff), not staged files; staging alone
is invisible to it. The isolated no-origin fixture above is the correct way to
exercise the trigger-matching logic directly, consistent with Phase 9b-2 and Phase 16a.
