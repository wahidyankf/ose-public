# 003 — Prerequisite Rubric and Evidence

Course frontmatter `prerequisites` decides two things: the "Prerequisites" links on a course page,
and — after this plan — which courses a path core must contain. Today the lists still encode an old
linear journey. This document defines what a true prerequisite is and records the decision for
every one of the 181 courses.

## Rubric

An edge "A requires B" is kept or added only when **all** tests pass:

| Test | Name               | Rule                                                                                                                                                                               |
| ---- | ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| T1   | Necessity          | A uses a concept, skill, or artifact that B teaches and A does not re-teach.                                                                                                       |
| T2   | Not optional       | A's own prose does not mark B as "helps", "not required", "companion", "contrast", "natural on-ramp", "absence does not block", "supporting", "recommended", or "broader context". |
| T3   | Not tooling-only   | Editor edges (Neovim) are dropped unless A's content uses that tool. Exceptions: `just-enough-lua` uses `vim.*` APIs throughout, and `extending-neovim` configures Neovim in Lua.  |
| T4   | Not a journey edge | The only reason for the edge is adjacency in an old manifest. Adjacency is never evidence.                                                                                         |

Two more rules refine T1 and T2:

- **L1 — language medium.** A language primer is a prerequisite when that language is A's primary
  code medium (every required exercise uses it). L1 overrides T2's wording: a course that calls Python
  "supporting" but writes every exercise in Python still requires `just-enough-python`.
- **C1 — capstones.** A capstone requires the courses whose artifacts it integrates, as named in its
  overview. A capstone depends on an earlier capstone only when it extends that capstone's codebase.

**No transitive reduction.** A course keeps every prior course its own prose names, even when that
course is already implied through another prerequisite. Reducing transitively would remove, for
example, SQL Essentials from the Advanced SQL page, where readers need to see it.

**Outline courses keep their edges.** The 62 outline courses have little or no prose to judge. Their
edges stay as they are until the course rewrite plans (06, 07, 08) re-run this rubric.

### Evidence Hierarchy

1. The course's own "Prerequisites" or "Prior topics" section in `overview.md` or
   `learning/overview.md`.
2. What the course content actually uses (language of the code, APIs, artifacts).
3. Old-manifest adjacency is a red flag, never a reason to keep an edge.

### Reason Codes

| Code       | Meaning                                                                                                |
| ---------- | ------------------------------------------------------------------------------------------------------ |
| K-PROSE    | Kept: the course's prerequisite prose names it as needed, or the content uses it (T1, L1).             |
| K-TOOL     | Kept under the T3 exception (`just-enough-lua` → `just-enough-nvim`).                                  |
| K-CAPSTONE | Kept under C1 (`capstone-forge-ready` → `extending-neovim`).                                           |
| K-OUTLINE  | Kept because the course is an outline; to be re-judged by its rewrite plan.                            |
| A-PROSE    | Added: the prose names it as needed, or the course's medium is that language (L1), and it was missing. |
| A-CAPSTONE | Added under C1: the capstone overview links and integrates that course's artifacts.                    |
| R-JOURNEY  | Removed under T4: the prose never names it; it only mirrored the old manifest order.                   |
| R-OPTIONAL | Removed under T2: the prose calls it optional, supporting, a companion, or broader context.            |
| R-SOURCE   | Removed: the needed artifact originates in another course that is already a prerequisite.              |
