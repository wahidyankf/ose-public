Event names (C1 lifecycle table): SessionStart, Setup, UserPromptSubmit, UserPromptExpansion, PreToolUse,
  PermissionRequest, PermissionDenied, PostToolUse, PostToolUseFailure, PostToolBatch, Notification, MessageDisplay,
  SubagentStart, SubagentStop, TaskCreated, TaskCompleted, Stop, StopFailure, TeammateIdle, InstructionsLoaded,
  ConfigChange, CwdChanged, DirectoryAdded, FileChanged, WorktreeCreate, WorktreeRemove, PreCompact, PostCompact,

Relevant to FERRET:
  session start/end        SessionStart, SessionEnd
  agent/subagent start/end SubagentStart, SubagentStop
  tool start/done/failure  PreToolUse, PostToolUse (success only), PostToolUseFailure
  skill invocation         PreToolUse/PostToolUse whose tool_name is `Skill` (Claude-initiated calls only) and

Input delivery: command hooks receive one JSON object on stdin (C1 "Hook input and output").
Common fields: session_id, prompt_id (v2.1.196+), transcript_path, cwd, scratchpad_dir (v2.1.257+),
  permission_mode, effort.level, hook_event_name. Inside a subagent or `--agent`: agent_id, agent_type.
Metadata per event (field names only):
  SessionStart      source (startup|resume|clear|compact|fork), optional model, agent_type, session_title;
                    resume/fork add seconds_since_last_response, context_tokens, prompt_cache_likely_expired,
                    estimated_cache_write_usd (v2.1.251+)
  SessionEnd        reason (clear|resume|logout|prompt_input_exit|other)
  SubagentStart     agent_id, agent_type            (cannot block subagent creation)
  SubagentStop      agent_id, agent_type, agent_transcript_path, stop_hook_active, last_assistant_message,
                    background_tasks, session_crons
  PreToolUse        tool_name, tool_input, tool_use_id (matches any tool except EndConversation, incl. Agent, Workflow, MCP)
  PostToolUse       tool_name, tool_input, tool_response, tool_use_id, duration_ms (optional; excludes permission
                    prompts and PreToolUse hooks). Foreground Agent-tool tool_response also has totalDurationMs.
  PostToolUseFailure tool_name, tool_input, tool_use_id, error (string, tool-specific text), is_interrupt (optional),
                    duration_ms (optional). Not fired for pre-execution rejections (unknown tool, invalid input,
                    permission denial) and not fired when a running tool is cancelled.
  UserPromptExpansion expansion_type (slash_command|mcp_prompt), command_name, command_args, command_source, prompt
                    (contains user text: the mapper must keep only command_name)
Parent/child: hook events inside a subagent carry the main session_id plus agent_id/agent_type.
Payload bounds: NO stdin/payload size limit is documented. Documented caps are on hook OUTPUT: additionalContext,
  systemMessage, initialUserMessage and plain stdout are capped at 10,000 characters (spilled to a file with a
  2,000-character preview); PostToolUseFailure `error` is middle-truncated by Claude Code.
Timeouts: `timeout` is in seconds; default 600 for command hooks (30 for UserPromptSubmit and model-switch events,
  10 for MessageDisplay). SessionEnd hooks share a 1.5-second default budget (applies on exit, /clear, and interactive
  /resume); a longer per-hook `timeout` raises the budget up to 60 s; env CLAUDE_CODE_SESSIONEND_HOOKS_TIMEOUT_MS
  overrides it. SessionEnd cannot block termination and its JSON output is discarded.
Async vs sync: hooks block Claude by default. `async: true` (command hooks only) runs in the background, cannot
  block or control Claude, and `timeout` is NOT enforced on it (the adapter's own watchdog must bound it). Each firing
  is a separate process with no deduplication. In `claude -p` (non-interactive) mode Claude Code kills any async hook
  still running at teardown and records outcome `cancelled`. Exit code 0 = success; only exit 2 blocks (on events that
  can block); other non-zero codes are non-blocking notices. Command hooks run in their own session with no
  controlling terminal. CLAUDE_PROJECT_DIR is exported to the hook process.
Trust (C1 "Workspace trust"; C2 "What runs before you trust a folder"):
  Interactive session: hooks from EVERY settings file (including .claude/settings.json) are held back until the user
  accepts the workspace trust dialog for the folder (or a parent whose trust extends to it).
  `claude -p` / SDK: no dialog is shown; the folder is treated as trusted and settings-file hooks RUN.
  Project subagent frontmatter hooks are stricter (not used in a never-trusted folder). `/hooks` is a read-only
  browser. `disableAllHooks` and managed `allowManagedHooksOnly` can switch hooks off. Settings edits are picked up
  by a file watcher during a session.
Skill detail: the `Skill` tool is listed in C3 ("Executes a skill within the main conversation"). The hooks page
  documents tool_input tables for Bash, PowerShell, Write, Edit, Read, Glob, Grep, WebFetch, WebSearch, Agent,
  AskUserQuestion, ExitPlanMode but NOT for `Skill`, so the field that carries the skill name inside a `Skill`
  tool_input is unverified; the UserPromptExpansion `command_name` field is documented.

    `.codex/hooks.json` changes the hash and requires re-trust on every machine.
N3. Codex SessionEnd default timeout is exactly 1 s (max 3 s), equal to FERRET's 1,000 ms cap: register it with an
    explicit larger `timeout` so the wrapper's own TERM 900 ms / KILL 1,000 ms watchdog binds first. Claude SessionEnd
    shares a 1.5 s budget across all SessionEnd hooks, leaving about 500 ms margin.
N4. OpenCode plugin hooks run in sequence with no documented timeout, and a thrown error in tool.execute.before blocks
    the tool: the plugin must not await the child for frequent events and must swallow every exception.
N5. Privacy allowlist inputs: Claude UserPromptExpansion carries `prompt`/`command_args`; Claude/Codex PostToolUse carry
    tool_input/tool_response and Claude PostToolUseFailure carries `error`; OpenCode carries output.args/output.output.
    Only event name, ids, tool/agent/skill names, outcome and duration are metadata.
N6. Claude and Codex subagent events share the main session_id; the child identity is agent_id.
N7. Cloud/other-platform behaviour was not probed; macOS and Linux are the only supported targets in the plan.
