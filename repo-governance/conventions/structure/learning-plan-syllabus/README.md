# Learning-Plan `syllabus/` Folder Convention

- [Learning-Plan Syllabus: Principles Implemented/Respected](./principles-implemented-respected.md) — The four core principles this convention implements — documentation-first deliverables, explicit triggers and ownership, a copy-paste template over a new directory, and a re-derivable measured tiering method. Read this to understand why the syllabus convention is shaped the way it is before applying its rules to a specific plan.
- [Learning-Plan Syllabus: Purpose](./purpose.md) — Why this convention exists — three learning-path plans authored large course/curriculum corpora with no governing rule for shape, ownership, or lifecycle. Read this for the one-paragraph problem statement behind the syllabus convention.
- [Learning-Plan Syllabus: Scope](./scope.md) — What the syllabus convention covers (trigger, folder layout, tiering, disposition, custody, grandfathering) versus what it explicitly leaves to the authoring plan or other governance. Read this to check whether a specific question — like course content quality or a deterministic validator — is covered by this convention or lies elsewhere.
- [The Learning-Bearing Trigger](./learning-bearing-trigger.md) — The decidable test for whether a plan's delivery checklist authoring or restructuring course/curriculum content brings it into scope, with worked positive and negative examples. Read this when deciding whether a new or existing plan must carry the syllabus folder layout, template-derived shape, and disposition/custody declarations.
- [Required Folder Layout](./required-folder-layout.md) — The syllabus/README.md, syllabus/courses/, and syllabus/paths/ structure every learning-bearing plan must carry, and which per-subfolder READMEs are grandfathered versus required. Read this when scaffolding a new corpus's syllabus folder or checking an existing one for a missing required file.
- [Corpus Census: Corpus Shapes](./corpus-census-corpus-shapes.md) — The measured file counts (course files, path manifests, README presence) across the three existing syllabus corpora that this convention's tiering rule is derived from. Read this when you need the raw per-corpus counts the section-tiering rule was measured against, before consulting the tiering evidence itself.
- [Corpus Census: Section Tiering Table](./corpus-census-section-tiering.md) — The measured section-frequency table across all 174 course files that the REQUIRED/RECOMMENDED/OPTIONAL tiering rule is derived from. Read this when you need the raw per-section frequency counts before applying the tiering rule and reproduction method.
- [Corpus Census: Tiering Rule and Reproduction](./corpus-census-tiering-rule.md) — The REQUIRED at 99%/RECOMMENDED at 80% tiering rule derived from the section-frequency table, the capstone carve-out, and the method for reproducing the measurement. Read this when applying or re-deriving the section tiers, or when checking whether a capstone-format file's missing sections are the known carve-out.
- [Copy-Paste Course Template](./copy-paste-course-template.md) — The three-tier (REQUIRED/RECOMMENDED/OPTIONAL) copy-paste markdown skeleton for authoring a new syllabus course file, matching the measured section tiering. Read this when starting a new syllabus/courses/<course-id>.md file — copy the REQUIRED skeleton, then add RECOMMENDED and OPTIONAL sections as they apply.
- [Corpus Disposition](./corpus-disposition.md) — The archive-with-plan versus promote-to disposition declaration every custodian plan carries in its selected technical form, the default rule, the promotion trigger test, and the corpus lifecycle diagram. Read this when writing a custodian plan's Corpus Disposition section in its selected technical form, or when deciding whether a corpus should switch from archive-with-plan to promote-to.
- [Custody Rule](./custody-rule.md) — The four custody rules governing custodian/consumer relationships over a syllabus corpus — single custodian, read-only consumers, routed change requests, and the two archival hand-off branches. Read this when a plan needs to reference or change content in another plan's syllabus corpus, or when a custodian plan is ready to archive while a consumer still links in.
- [Grandfathered Format Cohort](./grandfathered-format-cohort.md) — The 17-file ordered-list divergence inside plan 02's corpus, why it is identified as a separate authoring cohort, and why bullets are canonical for new course files while this cohort is not retrofitted. Read this when you find a course file using an ordered list for co-NN/ex-NN entries and need to know whether it is a known, accepted divergence or a new defect.
- [Conformance Recipe](./conformance-recipe.md) — The runnable grep-based bash loop that reports every course file missing a REQUIRED section, until a deterministic Rhino validator exists. Read this when you need to check an existing corpus for missing REQUIRED sections without a dedicated CLI validator.
- [Learning-Plan Syllabus: Related Documentation](./related-documentation.md) — Cross-references to the parent Plans convention, the UI Mockups precedent this convention mirrors, the Worktree Path structure convention, Knowledge Capture, and the governance architecture overview. Read this when you need the related-convention links this document cross-references rather than the rules themselves.
