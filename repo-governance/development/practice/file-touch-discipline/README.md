# File-Touch Discipline

- [File-Touch Discipline — Purpose and Scope](./purpose-and-scope.md) — The three observed failure modes that motivate File-Touch Discipline, and exactly what mutating operations and repositories this practice covers Use when you need to understand why File-Touch Discipline exists, or to check whether a specific kind of work (read-only, delegated, generated) is covered by it.
- [File-Touch Discipline — Standards 1-3: Opening and Building the Ledger](./standards-1-to-3.md) — The first three ledger standards - open before the first mutation, append at the moment of mutation with a reason, and never reconstruct the ledger from the working tree Use when starting a session that will mutate files, or when deciding what to write for each ledger entry.
- [File-Touch Discipline — Standards 4-5: Carrying and Losing the Ledger](./standards-4-to-5.md) — How the ledger survives context compaction and handoffs, and the degraded-mode default-deny behaviour required when it does not survive Use when writing a compaction summary or handoff, or when resuming a session and the ledger appears to be missing.
- [File-Touch Discipline — Standard 6: Reconciling Before Commit](./standard-6.md) — Comparing the ledger against the working tree in both directions before staging, and the bounded read-only diagnosis obligation for large foreign change sets Use immediately before staging or committing any change, and whenever a foreign change set looks unusually large or persistent.
- [File-Touch Discipline — Standards 7-8: Scope and Foreign Files](./standards-7-to-8.md) — The ledger is scoped to one (repository, worktree) pair, and foreign files not on the ledger get no action at all Use when working across multiple repositories or worktrees, or when you encounter a file that is not on your ledger.
- [File-Touch Discipline — Standard 9: Generated Mirrors](./standard-9.md) — Generated harness mirrors in the binding directories belong on the ledger and must land in the same commit as their canonical `.agents/` source, never a follow-up sync commit Use whenever you edit a file under the canonical `.agents/` directory, or any other file that has a generated mirror or derived artifact.
- [File-Touch Discipline — Anti-Patterns: Ledger Integrity](./anti-patterns-ledger-integrity.md) — Four anti-patterns that corrupt ledger integrity - post-compaction blanket staging, reconstructing authorship from the diff, tidying the tree, and trusting a clean-looking worktree Use when reviewing your own staging behaviour for signs of these four failure patterns, or when explaining why a specific staging shortcut is unsafe.
- [File-Touch Discipline — Anti-Patterns: Commit Hygiene](./anti-patterns-commit-hygiene.md) — Three anti-patterns that break commit hygiene - vague-prose ledgers, orphan sync commits, and hand-editing a generated mirror Use when writing ledger entries or deciding how to commit a canonical `.agents/` edit and its generated mirrors.
- [File-Touch Discipline — Agent Checklist and Related Documentation](./agent-checklist-and-related-docs.md) — A nine-point summary checklist for AI agents applying File-Touch Discipline, plus links to related conventions Use as a quick-reference checklist before and during any session that mutates files, or to find the conventions this practice relates to.
