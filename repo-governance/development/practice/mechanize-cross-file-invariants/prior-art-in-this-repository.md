# Prior Art In This Repository

This pattern already governs several cross-cutting invariants here, each independently arrived at
before being named as one general practice:

- **Harness bindings** (canonical `.agents/agents/` and `.agents/skills/` →
  `.opencode/agents/`, `.codex/agents/`, the generated region in `.codex/config.toml`, and
  non-vendored mirrors under `.agents/skills/`) — generated by `./rhino harness adapters generate`,
  checked by `./rhino harness adapters validate`. Vendored paths in those secondary roots remain
  hand-maintained. See [File-Touch Discipline](../file-touch-discipline.md) for the same-commit requirement this implies.
- **`repo-config.yml` schema parity** across the byte-identity-bound repos — `Rhino repo-config
validate` enforces an identical key set at parse time, so no repo can silently add or drop a key.
- **Git hooks** (`.husky/pre-commit`, `.husky/commit-msg`, `.husky/pre-push`) — thin shims that read
  `repo-config.yml`'s `gate:` surface at runtime via `./rhino gate list`/`gate run`, rather than
  hand-maintained command lists per hook.
- **Formatting** — the `format-staged` registry gate generates formatted bytes into the index at
  pre-commit and, on the pull-request surface, replays the same formatters over the changed paths
  and fails on any difference, so a hand-formatted file cannot drift from what the formatter would
  produce. (It replaced `package.json`'s generated `lint-staged` block, retired 2026-09-19.)
