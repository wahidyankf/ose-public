# Git Push Default Convention

- [Principles and Conventions Implemented](./principles-and-conventions-implemented.md) — The principles and companion conventions the Git Push Default Convention implements and respects. Use when tracing why the worktree-to-pr default and its precedence rules exist back to the principles and conventions they respect.
- [Scope](./scope.md) — What the Git Push Default Convention covers — delivery-mode push behaviour and checklist authoring — and what it explicitly defers to companion conventions. Use when determining whether a git-push question is governed by this convention or by one of its companions.
- [Standard 1: Default Integration Target Is a PR Branch](./standard-1-default-integration-target-is-a-pr-branch.md) — The default worktree-to-pr workflow, the situations it applies to, and the Phase 0 exception where no PR is opened at all. Use when confirming the default push behaviour for a delivery, or when checking whether Phase 0 of a plan should push or open a PR.
- [Standard 2: Direct Push Modes Are Explicit Selections, Not Inferred — and Are Repo-Restricted](./standard-2-direct-push-modes-are-explicit-selections-not-inferred-and-are-repo-restricted.md) — Per-repository availability of the two direct-push modes, and why no selection signal makes one available in ose-public. Use when a plan or invocation might call for pushing directly to origin main, to confirm the repository allows it.
- [Standard 3: Plans Must Declare a Delivery Mode Only to Override the Default](./standard-3-plans-must-declare-a-delivery-mode-only-to-override-the-default.md) — When plan-maker adds a Delivery Mode field, what plan-checker flags, and how plan-quality-gate and plan-execution resolve the mode. Use when authoring, checking, or fixing a plan's `## Delivery Mode` field.
- [Standard 4: Maintain Linear History Before Pushing](./standard-4-maintain-linear-history-before-pushing.md) — Rebase rather than merge before every push, and never let a merge commit reach main or a PR branch. Use before pushing when the remote may have moved forward since the last pull or push.
- [Standard 5: Proactively Fix Delivery-Mode Mismatches](./standard-5-proactively-fix-delivery-mode-mismatches.md) — Fix a mis-tagged or missing Delivery Mode field the moment you find one while reading delivery checklists, unless the plan is already archived. Use when reading a plan's delivery checklist and it mis-tags the merge step or assumes a stale push default.
- [Standard 6: Worktree Execution Does Not Determine the Mode by Itself](./standard-6-worktree-execution-does-not-determine-the-mode-by-itself.md) — Work location and integration target are independent axes; running from a worktree resolves to worktree-to-pr unless explicitly overridden. Use when an agent or session is running inside a git worktree and must decide which delivery mode applies.
- [Examples — Default and Direct-Push Selection](./examples-default-and-direct-push-selection.md) — PASS and FAIL examples of the default worktree-to-pr flow versus an unauthorized direct push. Use when checking whether a specific delivery transcript correctly used the default mode.
- [Examples — Plan-Maker Delivery-Mode Tagging](./examples-plan-maker-delivery-mode-tagging.md) — FAIL examples of a plan-maker assuming direct push without declaring a mode and mis-tagging git-mechanical steps [HUMAN], plus the corrected [AI]-tagged PASS example. Use when checking whether a plan-maker-authored delivery checklist declares its mode correctly and tags git-mechanical steps [AI].
- [Examples — Linear History and Proactive Fixes](./examples-linear-history-and-proactive-fixes.md) — PASS and FAIL examples of maintaining linear history before a push, and a PASS example of proactively fixing a preexisting delivery-mode mismatch. Use when checking whether a push sequence kept linear history, or whether a preexisting checklist mismatch was fixed rather than deferred.
- [Agent Responsibilities](./agent-responsibilities.md) — The per-agent responsibility table — plan-maker, plan-checker, plan-quality-gate, and the plan-execution workflow — for applying this convention. Use when identifying which agent owns a specific responsibility under the Git Push Default Convention.
