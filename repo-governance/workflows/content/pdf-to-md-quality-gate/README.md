# PDF-to-Markdown Quality Gate Workflow

- [Execution Mode](./execution-mode.md) — Describes the two execution modes for the PDF-to-Markdown quality gate: Agent Delegation (preferred) and Manual Orchestration (fallback), plus how a user invokes each. Use when deciding whether to run this workflow via delegated agents or manual tool orchestration.
- [Workflow Overview](./workflow-overview.md) — Mermaid flow diagram summarizing the maker-checker-fixer loop from start to pass/partial/fail. Use when you need a visual summary of the workflow's control flow before reading the detailed steps.
- [1. Generate Markdown (Conditional)](./step-1-generate-markdown.md) — Step 1: conditionally invokes pdf-to-md-maker to convert the source PDF to Markdown when no Markdown file exists yet or force-remake is set. Use when implementing or debugging the conditional Markdown-generation step of the quality gate.
- [2. Validate Fidelity (Sequential)](./step-2-validate-fidelity.md) — Step 2: invokes pdf-to-md-checker to validate the generated Markdown against the source PDF across all fidelity dimensions. Use when implementing or debugging the fidelity-validation step of the quality gate.
- [3. Check for Findings (Sequential)](./step-3-check-for-findings.md) — Step 3: counts checker findings by mode threshold and decides whether to proceed to fixing or to a confirmation re-check. Use when implementing or debugging the findings-threshold decision step of the quality gate.
- [4. Apply Fixes (Sequential, Conditional)](./step-4-apply-fixes.md) — Step 4: invokes pdf-to-md-fixer to apply validated fixes by mode, including the confidence-downgrade rules that force MEDIUM_CONFIDENCE (manual review) instead of auto-apply. Use when implementing or debugging the fix-application step, or when determining whether a fix should be auto-applied or downgraded for manual review.
- [5. Re-validate (Sequential)](./step-5-revalidate.md) — Step 5: re-runs pdf-to-md-checker after fixes to confirm resolution, including scoped re-validation and the carry-forward audit for zero-applied-fix iterations. Use when implementing or debugging the re-validation step, especially the scoped-scan and carry-forward-audit behaviour.
- [6. Iteration Control (Sequential)](./step-6-iteration-control.md) — Step 6: the iteration-control logic tracking consecutive-zero counts and consecutive-zero-fixes to decide pass, partial (stagnation exit), or loop back. Use when implementing or debugging the loop/termination decision logic between checker and fixer iterations.
- [7. Finalization (Sequential)](./step-7-finalization.md) — Step 7: reports the final status (pass/partial/fail), iteration count, and summary report. Use when implementing or debugging the workflow's final reporting step.
