- [Purpose, Scope, and When to Use](./purpose-scope-and-when-to-use.md) — Explains why the plan-multi-repo-parity-planning-and-execution composite exists and when to use it versus its standalone constituents. - [Execution Mode and Task List Contract](./execution-mode-and-task-list-contract.md) — States that direct orchestration is mandatory and defines the composite-wide granular Task list contract that keeps the live task list in sync with disk. Use when starting the composite, to confirm orchestration mode and set up the live Task list correctly.
- [Step 1 — Planning Phase](./step-1-planning-phase.md) — Runs the nested plan-multi-repo-parity-planning workflow in full, with composite-specific constraints on stage and mode. Use when executing the composite's first step — authoring and gating one plan per repo before any execution begins.
- [Step 2 and 3 — Phase Gate and Pre-Execution Grill](./step-2-and-3-phase-gate-and-pre-execution-grill.md) — The hard-gate check that every plan is execution-ready, followed by the third (pre-execution) grill on order, failure policy, and worktree cleanup. Use before starting the execution phase, to verify readiness and record the operational decisions that govern it.
- [Step 4 — Execution Phase](./step-4-execution-phase.md) — Runs plan-execution in full for each repo's gated plan, inheriting its Delivery Mode resolution, worktree gate, Task list expansion, Iron Rules, and archival. Use when executing the composite's per-repo execution step and needing the exact plan-execution rules that apply.
- [Step 4 — Execution Phase (Continued)](./step-4-execution-phase-propagation-and-delivery.md) — Covers propagation shape, the parity-manifest gate, per-repo delivery shape, and shared-machine safety. Use when deciding whether to run repos concurrently, or the parity-manifest gate fires.
- [Step 5 — Cross-Repo Finalization](./step-5-cross-repo-finalization.md) — The final composite step — repairing sibling cross-links, verifying the parity outcome, and reporting composite-wide results. Use after the last repo's execution completes, to close out the composite run.
- [Termination Criteria and Grilling Contract](./termination-criteria-and-grilling-contract.md) — Defines the composite's pass/partial/fail outcomes and summarizes its three mandatory hard-gated grill sessions. Use when determining the composite's final status, or confirming which grill sessions are required before proceeding.
- [Example Usage](./example-usage.md) — Two worked examples of invoking the composite — both parity repos, and a single-repo subset. Use when constructing an invocation of this workflow or explaining its behaviour with a concrete example.

Use when auditing this workflow's governance alignment or looking up which agent performs a given phase.
