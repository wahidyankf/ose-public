# Plan Multi-Repo Parity Planning Workflow

- [Purpose, Scope, and When to Use](./purpose-scope-and-when-to-use.md) — Explains why plan-multi-repo-parity-planning exists, the precedent that motivated it, and when to use it. Use when deciding whether a cross-repo objective needs this workflow's grilling discipline.
- [Execution Mode](./execution-mode.md) — States the preferred Agent Delegation execution mode, the Manual Orchestration fallback, and the orchestrator's eight-step outline. Use when starting this workflow, to confirm which execution mode applies and what the orchestrator does step by step.
- [Propagation, Delivery Shape, and Shared-Machine Safety](./propagation-delivery-and-machine-safety.md) — Covers logically independent propagation, HIPPO-controlled cross-repository compute, surviving correctness edges, per-repo delivery shape, and shared-machine safety. Use when scheduling repository work, classifying guarded nodes, or preparing cleanup.
- [Invocation Point and Modes Overview](./invocation-point-and-modes-overview.md) — Where this workflow runs from, and the two non-default delivery modes for the plan documents it authors — main-to-origin-main and worktree-to-origin-main. Use when determining the anchor repo for a run, or choosing a direct-push delivery mode for the plan documents themselves.
- [`worktree-to-pr` (Default)](./modes-worktree-to-pr-default.md) — The repo-wide default delivery mode for the plan documents this workflow authors, plus the bare-repo parity-target exception. Use when delivering the authored plan documents under the repo-wide default review-before-merge mode.
- [Relationship to Each Repo's Own `## Delivery Mode`](./relationship-to-delivery-mode.md) — Distinguishes this workflow's own plan-document delivery mode from each authored plan's separately-declared, independently-resolved execution Delivery Mode. Use when confused about which "delivery mode" a decision refers to — the plan document's or the plan's own future execution.
- [Step 1 — Parity-Set Survey](./step-1-parity-set-survey.md) — Empirically surveys every target repo's current state, including the Rhino byte-identity check and the survey-freshness re-run rule. Use when starting a parity run, to build the per-repo state inventory the deviation matrix is built from.
- [Step 2 — Gap and Deviation Matrix Construction](./step-2-gap-and-deviation-matrix.md) — Builds the deviation matrix by diffing per-repo inventories dimension-by-dimension, including the required meta-dimensions. Use after the survey, to construct the matrix that Step 3's grill will resolve row by row.
- [Step 3 — First Grill](./step-3-first-grill.md) — The hard-gated grilling protocol that resolves every deviation-matrix row to a recorded decision and establishes the research-needed flag. Use when resolving cross-repo deviations before any plan authoring — this grill is a hard gate on Step 6.
- [Step 3 — First Grill (Mandatory Meta-Questions)](./step-3-first-grill-meta-questions.md) — The four mandatory meta-questions every First Grill session must surface — bare-repo delivery mode, rationale-doc location, repo-specific constraints, and research-needed. Use when closing out the First Grill, to confirm every mandatory meta-question was asked and recorded.
- [Step 4 and 5 — Web Research and Second Grill](./step-4-and-5-research-and-second-grill.md) — The conditional web-research delegation and the post-research grill that validates direction before plan authoring. Use when the research-needed flag is set, or when validating decisions against research findings before Step 6.
- [Step 6 — Plan Authoring](./step-6-plan-authoring.md) — Authors the mature-core plan per repo via plan-maker, with the required handoff prompt including delivery-mode instructions. Use when authoring each repo's plan after both grills close, to build the plan-maker handoff correctly.
- [Step 6 — Plan Authoring (Required Contents)](./step-6-plan-authoring-required-contents.md) — The five required contents of every authored plan — full deviation matrix, sibling cross-links, rationale doc item, governance-update item, and Knowledge Capture. Use when verifying an authored plan carries everything this workflow requires before it can pass the quality gate.
- [Step 7 and 8 — Quality Gate and Delivery](./step-7-and-8-quality-gate-and-delivery.md) — Runs plan-quality-gate per plan to a PASS verdict, then delivers per the selected mode and reports the deviation count summary. Use when gating and delivering the authored plans, or reporting the run's final outcomes.
- [Delivering the Parity Plans](./delivering-the-parity-plans.md) — Carries gated parity plans on to delivery in the same run through a readiness gate, a pre-execution grill, DAG execution per repository, and cross-repository finalization. Use when the parity plans this workflow authored should be executed and delivered in the same run.
- [Termination Criteria and Grilling Contract](./termination-criteria-and-grilling-contract.md) — Defines pass/partial/fail outcomes and summarizes why the workflow's grilling is intentionally exhaustive. Use when determining the workflow's final status, or understanding why every cross-repo difference must be grilled.
- [Example Usage](./example-usage.md) — Three worked examples — default worktree-to-pr, direct push with backlog stage, and a single-repo subset. Use when constructing an invocation of this workflow or explaining its behaviour with a concrete example.
- [Safety Features and Related Workflows](./safety-features-and-related-workflows.md) — Lists the workflow's safety guarantees (worktree isolation, gate-before-delivery, hook compliance, secrets rule) and links to related workflows. Use when verifying what protections this workflow provides, or navigating to a related workflow.
- [Principles and Conventions Implemented/Respected](./principles-and-conventions.md) — Lists the principles and conventions this workflow implements, for governance-alignment auditing. Use when auditing this workflow's governance alignment or citing which principle or convention a rule traces to.
